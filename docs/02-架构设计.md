# 02 · 架构设计

## 核心原则：React 不负责系统能力

不要做成这样：

```
React
 ├── 剪贴板
 ├── SQLite
 ├── 文件
 └── 快捷键
```

而是这样：

```
React  →  "我要历史记录，按 jwt 过滤"
   ↓  Tauri IPC
Rust   →  查询
   ↓
SQLite
```

好处：换 Windows / Linux 时，核心逻辑不乱；前端可以脱离 Rust 单独开发与测试。

## 端口-适配器：前端如何脱离 Rust 开发

`src/lib/` 下定义接口 + 两套实现，编译期切换。

```
src/lib/api.ts          ← interface ClipboardApi（唯一的契约）
src/lib/api.mock.ts     ← 内存假数据，阶段 1 用，零 Rust 依赖
src/lib/api.tauri.ts    ← 真实实现，invoke() 到 Rust
src/lib/api/index.ts    ← 按 import.meta.env 导出其中一个
```

```ts
// src/lib/api.ts
export type ContentType =
  | "text" | "code" | "json" | "jwt" | "sql"
  | "url" | "uuid" | "base64" | "ip"
  | "exception" | "commit" | "markdown" | "image";

export interface ClipboardItem {
  id: number;
  content: string;
  contentType: ContentType;
  preview: string;
  imagePath?: string;
  byteSize: number;
  copyCount: number;
  sourceApp?: string;
  createdAt: number;
  lastCopiedAt: number;
  favorite: boolean;
  sensitive: boolean;
}

export interface Query {
  text?: string;         // 关键词
  types?: ContentType[]; // 内容类型过滤
  favoriteOnly?: boolean;
  since?: number;        // 时间范围（毫秒时间戳）
  limit?: number;
  offset?: number;
}

export interface ClipboardApi {
  list(q: Query): Promise<ClipboardItem[]>;
  get(id: number): Promise<ClipboardItem | null>;
  toggleFavorite(id: number): Promise<boolean>;
  remove(ids: number[]): Promise<void>;
  clearAll(): Promise<void>;

  copyToClipboard(id: number): Promise<void>;
  paste(id: number): Promise<void>;          // 写入剪贴板 + 模拟 ⌘V
  runToolboxAction(id: number, action: string): Promise<string>;

  detect(raw: string): Promise<ContentType>; // 供设置页 / 调试用
  availableActions(contentType: ContentType): Promise<ToolboxAction[]>;

  // 快捷键配置
  getHotkey(): Promise<string>;
  setHotkey(accel: string): Promise<void>;    // 冲突时 reject

  // 设置
  getSettings(): Promise<Settings>;
  setSettings(patch: Partial<Settings>): Promise<Settings>;
}
```

```ts
// src/lib/api/index.ts
import type { ClipboardApi } from "./api";
import { mockApi } from "./mock";
import { tauriApi } from "./tauri";

export const api: ClipboardApi = import.meta.env.DEV_USE_MOCK
  ? mockApi
  : tauriApi;
```

Mock 实现在 `import.meta.env.DEV_USE_MOCK` 打开时使用；一旦接上 Rust，只改这一行的判断条件即可。

**这样做的好处**：阶段 1 纯 TS 就能把列表 / 搜索 / 收藏 / 键盘导航的交互全部做完并调好，阶段 3 起来时前端一行都不用改。

### 关键 trait：平台差异全部收敛在这里

```rust
#[async_trait]
pub trait ClipboardMonitor: Send + Sync {
    /// 开始监听。回调在后台任务里触发。
    fn start(&self, on_change: Box<dyn Fn(ClipEvent) + Send + Sync>);
    fn stop(&self);
}

pub struct ClipEvent {
    pub text:  Option<String>,
    pub image: Option<ImagePayload>,   // 原始字节
}
```

工厂按 `cfg(target_os)` 编译期选择：

```rust
pub fn create_monitor() -> Box<dyn ClipboardMonitor> {
    #[cfg(target_os = "macos")]
    { Box::new(macos::MacosMonitor::new()) }
    #[cfg(target_os = "windows")]
    { Box::new(windows::WindowsMonitor::new()) }
    #[cfg(all(unix, not(target_os = "macos")))]
    { Box::new(x11::X11Monitor::new().or_else(|_| wayland::WaylandMonitor::new()).unwrap()) }
}
```

新增一个平台 = 新增一个文件 + 一行 `cfg`，其余代码不动。

## 事件流

```
① 系统剪贴板变化
      ↓
② ClipboardMonitor 回调
      ↓
③ 自抑制判断        ← 是不是 DevClip 自己写进去的？（回环保护）
      ↓
④ 与当前内容比对    ← 一样就丢弃
      ↓
⑤ detect(content)   ← 判定 ContentType
      ↓
⑥ 敏感信息扫描      ← sk_live_* / AKIA* / PRIVATE KEY / JWT
      ↓
⑦ repo.upsert()     ← hash 命中则累加 copy_count，否则插入
      ↓
⑧ emit("clipboard://changed", item)  ← 通知前端刷新
```

第 ③ 步用一个全局 `AtomicU64` 记录"我们自己最后一次写入内容的 hash"：

```rust
static OWN_WRITE: AtomicU64 = AtomicU64::new(0);

pub fn suppress_next(content_hash: u64) { OWN_WRITE.store(content_hash, Ordering::SeqCst); }
```

监听器收到事件时比对，命中则跳过。不做这一步，用户每点一次"Format 并复制"就会多出两条历史。

## IPC 事件（Rust → 前端）

| 事件名 | 触发时机 | 载荷 |
|---|---|---|
| `clipboard://changed` | 新增或命中已有条目 | `ClipboardItem` |
| `hotkey://triggered` | 全局快捷键按下 | `null` |
| `hotkey://error` | 快捷键注册失败 / 冲突 | `{ accel, message }` |
| `settings://changed` | 设置变更 | `Settings` |
| `permission://required` | 缺少辅助功能等授权 | `{ kind, hint }` |

## 窗口行为（调色板的关键细节）

调色板窗口不是一个普通窗口，以下都是必需的：

| 需求 | 做法 |
|---|---|
| 平时不可见 | 启动时不显示，收到 `hotkey://triggered` 才 `show()` |
| 不出现在任务栏 | `skipTaskbar: true` |
| 置顶 | `alwaysOnTop: true` |
| 失焦即隐藏 | `on_blur` → 隐藏（但要防抖，避免切窗口瞬间消失） |
| 位置 | 跟随鼠标所在屏幕居中，而不是主屏 |
| 抢焦点 | Windows 需 `SetForegroundWindow`，macOS 需 `activate` + `NSApp.activate` |
| 键盘独占 | 获得焦点后所有按键都进搜索框，用 `cmdk` 的默认行为即可 |

窗口相关配置放 `tauri.conf.json` 的 `app.windows[0]`。
