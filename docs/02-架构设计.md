# 02 · 架构设计

> 这份文档已按实现订正过一轮（2026-10-02）。凡是与代码不一致的地方，
> 都在原地标了「与最初设想的出入」并写明原因 —— 设计稿上的名字和
> 做法留在那儿没有意义，照抄的人会被带偏。

## 核心原则：React 不负责系统能力

不要做成这样：

```
React
 ├── 剪贴板
 ├── SQLite
 ├── 文件
 └── 快捷键
```

而是这样：

```
React  →  "我要历史记录，按 jwt 过滤"
   ↓  Tauri IPC
Rust   →  查询
   ↓
SQLite
```

好处：换 Windows / Linux 时，核心逻辑不乱；前端可以脱离 Rust 单独开发与测试。

## 端口-适配器：前端如何脱离 Rust 开发

`src/lib/` 下定义接口 + 两套实现，编译期切换。

```
src/lib/api.ts          ← interface ClipboardApi（唯一的契约，14 个方法）
src/lib/mock.ts         ← 内存假数据，零 Rust 依赖
src/lib/tauri.ts        ← 真实实现，invoke() 到 Rust
src/lib/backend.ts      ← 全应用唯一一处分叉：impls 表 + 运行时探测
```

**两个咽喉点就是 `api.ts` 与 `backend.ts`**，新增能力先想清楚落在哪一侧。
组件与 store 不得直接调 `invoke()`。

```ts
// src/lib/api.ts
export type ContentType =
  | "text" | "code" | "json" | "jwt" | "sql"
  | "url" | "uuid" | "base64" | "ip"
  | "exception" | "commit" | "markdown" | "image";

export interface ClipboardItem {
  id: number;
  content: string;
  contentType: ContentType;
  preview: string;
  imagePath?: string;
  byteSize: number;
  copyCount: number;
  sourceApp?: string;
  createdAt: number;
  lastCopiedAt: number;
  favorite: boolean;
  sensitive: boolean;
}

export interface Query {
  text?: string;         // 关键词
  types?: ContentType[]; // 内容类型过滤
  favoriteOnly?: boolean;
  includeSensitive?: boolean; // 默认关，敏感项不参与普通结果
  since?: number;        // 时间范围（毫秒时间戳）
  limit?: number;
  offset?: number;
}

export interface ClipboardApi {
  list(q: Query): Promise<ClipboardItem[]>;
  get(id: number): Promise<ClipboardItem | null>;
  toggleFavorite(id: number): Promise<boolean>;
  remove(ids: number[]): Promise<void>;
  clearAll(): Promise<void>;

  copyToClipboard(id: number): Promise<void>;
  paste(id: number): Promise<void>;          // 写入剪贴板 + 模拟 ⌘V

  availableActions(t: ContentType): Promise<ToolboxAction[]>;
  runToolboxAction(id: number, actionId: string): Promise<ActionResult>;

  getSettings(): Promise<Settings>;
  setSettings(patch: Partial<Settings>): Promise<Settings>;
  setHotkey(accel: string): Promise<string>;  // 返回规范化后的串

  monitorStatus(): Promise<string | null>;    // 监听不可用的原因

  subscribe(
    onChanged: () => void,
    onNotice?: (text: string) => void,
  ): () => void;
}
```

**14 个方法。** 四处与最初的设想不同，都是被现实改的：

- **没有 `detect()`。** 识别只在入库那一步跑，暴露它只会让人绕过
  `repo` 直接写库
- **没有 `getHotkey()`。** 快捷键在 `Settings` 里，读设置就够了；
  而改快捷键单独一个方法，因为它有「注册系统钩子」这种立即生效的
  副作用，失败方式也不同（可能被别的应用占用）
- **`runToolboxAction` 返回 `ActionResult` 而不是结果字符串。** 结果是
  **写进系统剪贴板**的，返回值只是一句摘要给状态栏显示 ——
  格式化后的 JSON 几 KB，状态栏一行、2.6 秒自动消失，塞不下也不该塞
- **`monitorStatus()` 是问出来的，不是听出来的。** 能不能监听在
  `setup()` 里就定了，而 webview 是那之后才加载的 —— 早先发
  `clipboard://unavailable` 事件，那个事件永远送不到前端

窗口层的事（收起面板、进入拖动、托盘的「设置」）**不进这个契约** ——
它讲的是剪贴板历史，窗口显隐是另一回事。但分派仍留在 `backend.ts`，
组件不直接引 `./tauri`。

```ts
// src/lib/backend.ts
const impls: Record<string, ClipboardApi> = {
  mock: mockApi,
  tauri: tauriApi,
};

export const backendName =
  import.meta.env.VITE_BACKEND || (isTauri() ? "tauri" : "mock");

export const api: ClipboardApi = impls[backendName] ?? mockApi;
```

**默认按运行环境探测，不看环境变量。** 早先这里写死 `|| "mock"`，
结果 `pnpm tauri dev` 起来的真应用也走 mock —— Rust 那套剪贴板与数据库
一行都不会被执行。靠 `.env` 也不合适：e2e 跑在浏览器里，一旦全局设成
tauri，`invoke` 全都会 reject。运行时探测两种场景才对。

**这样做的好处**：阶段 1 纯 TS 就能把列表 / 搜索 / 收藏 / 键盘导航的交互全部做完并调好，阶段 2 接上 Rust 时前端一行都不用改。

## Rust 模块划分

```
src-tauri/src/
├── main.rs            入口
├── lib.rs             run() + 17 个 #[tauri::command] + 托盘 / 窗口 / 后台任务
├── clipboard.rs       读 / 写 / 清空、前台应用、模拟粘贴、两个平台的监听循环
│   └── linux.rs       X11 Selection 接管 + Wayland 检测 + XTEST 按键
├── detect.rs          内容类型识别（纯函数，第一个写的文件）
├── sensitive.rs       密钥识别（纯函数）
├── repo.rs            SQLite repository + ClipboardItem 与其 serde
├── db.rs              连接管理、建表、FTS5
├── settings.rs        配置持久化
├── hotkey.rs          全局快捷键注册 / 冲突检测
└── toolbox/
    ├── mod.rs         action 注册表 + 分发
    ├── json.rs  jwt.rs  sql.rs
    ├── b64.rs   url_tool.rs  uuid_tool.rs
```

与最初设想的出入，都是「一个文件只有一两样东西时不开文件」：

- **没有 `error.rs`。** 全用 `Result<_, String>`，错误文案要能直接
  展示给用户，包一层自定义错误类型没换来什么
- **没有 `models.rs`。** `ClipboardItem` 只有一个结构体，和它的 serde
  一起放在 `repo.rs` 顶部
- **没有 `paste.rs`。** 模拟粘贴与读写剪贴板是同一件事（都要处理
  回环保护），放一起更清楚；平台差异靠 `cfg` 的两份同名函数收敛
- **监听没有按平台分文件，只分了 Linux 一个。** macOS 与 Linux 的
  循环差异大到没法共用一套抽象，见下

## 平台差异：没有 trait，按 cfg 分派

最初的设计是给每个平台一个 `ClipboardMonitor` 实现，工厂返回
`Box<dyn ClipboardMonitor>`。**实现时没做 trait，而是 `spawn_watcher`
内部按 `cfg` 分派到 `spawn_macos` / `spawn_linux`。**

理由是强行套 trait 只得到一堆样板方法：两个平台的循环在**轮询什么、
怎么判重复、失败怎么办**上都不一样，最后每个方法都在返回默认值。
等到平台差异大到需要各自的回环处理时，trait 就成了负担而不是抽象。

## 事件流

```
① 系统剪贴板变化
      ↓
② 平台监听循环读到内容
      ↓
③ 自抑制判断        ← 是不是 DevClip 自己写进去的？（回环保护）
      ↓
④ 与上一条比对      ← 一样就丢弃（Seen 去抖）
      ↓
⑤ detect(content)   ← 判定 ContentType
      ↓
⑥ 敏感信息扫描      ← 私钥块 / AKIA / GitHub PAT / sk_live_ / xoxb-
      ↓
⑦ repo.upsert()     ← hash 命中则累加 copy_count，否则插入
      ↓
⑧ emit("clipboard://changed", item)  ← 通知前端刷新
```

第 ③ 步是**两个**结构，不是一个 hash：

```rust
pub struct SelfWrite(Mutex<Option<String>>);  // 我们自己最后写进去的内容
pub struct Seen(Mutex<Option<String>>);       // 上一轮观察到的内容
```

`SelfWrite` 挡自己写进去的内容被重新捕获；`Seen` 做去抖。**去抖窗口
必须每次观察都推进** —— 只在内容变化时更新时间戳的话，按住 Ctrl+C
十秒会把 `copy_count` 刷到 11（`ea56af7`）。

不做回环保护，用户每点一次「美化并复制」就会多出两条历史。

## IPC 事件（Rust → 前端）

| 事件名 | 触发时机 | 载荷 | 前端 |
|---|---|---|---|
| `clipboard://changed` | 新增 / 命中已有 / 删除 | `ClipboardItem` 或 `{}` | 监听，当「该刷新了」的信号 |
| `clipboard://notice` | 降级提示（模拟粘贴失败、请手动粘贴） | `{ text }` | 监听，进状态栏 |
| `settings://open` | 托盘菜单点「设置」 | `()` | 监听，打开设置页 |

**快捷键没有事件。** 最初设想 `hotkey://triggered` 来呼出面板，
实际是 Rust 侧直接 `show_palette()` + 抢焦点 —— 多发一个事件让前端
再绕回来没有任何好处。

**「监听不可用」也不走事件。** 早先发过 `clipboard://unavailable`，
但那是在 `setup()` 里发的，webview 还没加载，**没有任何前端能收到**。
现在存进 managed state，由 `monitorStatus()` 在 `init()` 时问一次。

## 窗口行为（调色板的关键细节）

调色板窗口不是一个普通窗口，以下都是必需的：

| 需求 | 做法 |
|---|---|
| 平时不可见 | 启动时不显示，快捷键按下才 `show()` |
| 不出现在任务栏 | `skipTaskbar: true` |
| 置顶 | `alwaysOnTop: true` |
| 失焦即隐藏 | 失焦即隐藏（要防抖，避免切窗口瞬间消失） |
| 位置 | 跟随鼠标所在屏幕居中，而不是主屏 |
| 抢焦点 | macOS 用进程内 `NSRunningApplication.activate`；**不用 osascript** —— 那会触发 TCC「自动化」弹窗，弹窗不出现时调用方会一直等，而它当时持着数据库锁 |
| 键盘独占 | ⚠️ **不是**用 cmdk 的默认行为，见下 |

**键盘导航已经从 cmdk 手里拿走了。** cmdk 靠在 DOM 里查
`[cmdk-item][aria-selected="true"]` 定位当前项，`↑↓` 也在**已渲染**的项
之间跳。列表虚拟化之后它只看得到窗口内的项，两处都会算错，`Enter`
甚至会静默失效。现在 `↑↓` 由 `Palette` 自己管，cmdk 只留 `Input` /
`Empty` / `Item` 的 aria 与点击。

**要守住一条：selected 那一项必须始终留在 DOM 里** —— `VirtualList`
用 pin 区间 + 滚动 effect 兜底。

窗口相关配置放 `tauri.conf.json` 的 `app.windows[0]`。
