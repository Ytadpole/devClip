# 04 · 内容识别与工具箱

这是 DevClip 与普通剪贴板管理器的分界线：**不只是存下来，而是理解它**。

## 识别顺序

`detect.rs` 必须**按顺序**判定，先匹配到的胜出。顺序错了会把 SQL 认成 code、把 JSON 认成 text。

```
1. image            —— 非文本 flavor
2. json             —— 可被解析为 JSON
3. jwt              —— 三段 base64url，段1/段2 可解出含 typ/alg 等字段
4. uuid             —— 标准 8-4-4-4-12
5. ip               —— IPv4 / IPv6（注意要和 UUID 区分，UUID 有连字符）
6. url              —— 有 scheme 的合法 URL
7. commit           —— `^[0-9a-f]{7,40}$`（先排除 纯数字误判）
8. exception        —— 匹配到异常栈特征
9. sql              —— 命中 SQL 关键字组合
10. base64          —— 长度 % 4 == 0 且解码成功且解码结果可打印
11. markdown        —— 含 ``` 围栏，或 `^#{1,6} ` / `](` / `- [ ]` 命中 2 类
12. code            —— 多行 + 缩进 + 常见语言特征
13. text            —— 兜底
```

### 每条规则的具体判据

| 类型 | 判据 | 注意 |
|---|---|---|
| `json` | `serde_json::from_str::<Value>()` 成功 | 失败则继续往下 |
| `jwt` | `split('.').count() == 3` + 每段是合法 base64url + header 解出 JSON 含 `alg` | **三段但解不出 header 的不算 JWT**（普通 base64 也可能三段） |
| `uuid` | 正则 `^[0-9a-fA-F]{8}-([0-9a-fA-F]{4}-){3}[0-9a-fA-F]{12}$` | |
| `ip` | 用 `std::net::IpAddr::from_str` | IPv6 优先判断，因为不含点 |
| `url` | `url::Url::parse` 成功 + scheme ∈ {http, https, ftp, ws, wss, file, git} | **`git@github.com:user/repo.git` 要单独用 SSH 正则匹配** |
| `commit` | `^[0-9a-f]{7,40}$` | 纯数字全匹配时要排除（可能是订单号） |
| `exception` | 命中 `^[\w.$]+(Exception|Error)\b` 或 `at [\w.$]+\([\w]+\.java:\d+\)` 或 `Traceback (most recent call last)` | 多语言特征并列。**类名可以不带包名**：`RuntimeError: msg` 也算，但要求冒号后有空白（要有 message），否则 `there was an Exception yesterday` 会误判 |
| `sql` | 至少 2 个关键字（`SELECT` `FROM` `WHERE` `JOIN` `INSERT` `UPDATE` `DELETE` `GROUP BY`…）**且** 大小写不敏感 | 单个 "select" 不算，必须 2 个。**DDL 例外**：`CREATE TABLE` / `CREATE INDEX` / `CREATE VIEW` / `ALTER TABLE` / `DROP TABLE` **单个就定性** —— `CREATE TABLE users (...)` 全文只有一个 SQL 关键字；且必须匹配行首 |
| `base64` | 长度 ≥ 8、长度 % 4 == 0、字符集合法、解码后 UTF-8 且可打印 | 排除本身就是纯数字/纯十六进制的情况 |
| `markdown` | 含 `` ``` `` 围栏即定性；否则行首 `#{1,6} `、`](` 链接、`- [ ]` 任务项命中 2 类 | 围栏不能再要求凑第二类：它和 code 的区别就在这对 ``` |
| `code` | 行数 ≥ 3，且（存在 2 空格以上缩进 / 命中语言关键字 / 命中 `{` `}` `;` 配对） | 放在 SQL 之后 |

**`source_app` 可以加权判定。** 复制来源是 `IntelliJ IDEA` / `VS Code` / `DataGrip` 时，即使是 code，也尝试更激进地识别为 sql / json / code。这需要平台提供前台应用信息（macOS 有 `NSWorkspace.frontmostApplication`），是 P1 的差异化点。

## 动作注册表（Rust 侧）

用注册表而不是一长串 `match`，这样加新类型不用动分发逻辑。
实际代码在 `src-tauri/src/toolbox/mod.rs`：

```rust
pub struct Entry {
    pub id: &'static str,
    pub label: &'static str,
    pub hint: Option<&'static str>,
    pub applies_to: &'static [ContentType],
    pub run: fn(&str) -> Result<String, String>,
}
```

`run` **不吃 `AppHandle`**，与原始设计一致。这不是为了简化，是因为
可测：SQL 格式化那种逻辑需要一个不需要起 Tauri 应用的单元测试。
需要应用句柄的动作（打开浏览器）不进注册表，走单独的 command。

前端调用 `availableActions(contentType)` 拿到该类型可用的操作列表，UI 直接渲染。**这样前端不需要硬编码任何类型判断逻辑。**

## 实际实现（2026-09-29，阶段 6）

### 动作清单

| 类型 | 动作 |
|---|---|
| `json` | 美化（2 空格）· 美化 (4 空格) · 压缩 |
| `jwt` | 解 Header · 解 Payload · 检查过期 |
| `base64` | 解码 · 解码 (url-safe) · 编码 · 编码 (url-safe) |
| `sql` | 格式化 · 关键字大写 · 关键字小写 · 提取表名 |
| `url` | 去掉 query · 提取域名 |
| `uuid` | 转大写 · 转小写 · 去横线 |
| `text` / `code` | 复用 base64 那两条「编码」，不另注册 |

`ip` / `commit` / `exception` / `markdown` / `image` 没有动作，工具条不显示。

**注册表里是 19 条，不是表里相加的 21。** `text` / `code` 挂的是
`b64.encode` 与 `b64.encode_urlsafe` **同两条 entry**（`applies_to`
里多列了两种类型），不是新动作。代价是选中任何一句话都会出现工具条 ——
对开发者工具可以接受，换来「把一段命令编成 base64」不用先换类型。

### 与上方设计稿的四处偏离

**1. 没有 `json.sort_keys`，因为它是个空操作。** `serde_json::Map`
默认是 `BTreeMap`，除非显式开 `preserve_order` feature，否则序列化出来
天然按字母序。查过依赖树（`cargo tree -i serde_json -e features`），
`preserve_order` 确实没被打开。所以 `美化` 的输出已经排序过了，
再挂一个同名动作只会让用户以为「不点就没排」。**要真的排序得先开
`preserve_order`，那是给另一个用户群体用的。**

**2. 结果写进剪贴板**并**直接粘贴**，命令只返回一句摘要。** 设计稿里
`runToolboxAction` 返回结果字符串，但格式化后的 JSON 动辄几 KB，
调色板状态栏只有一行、2.6 秒后自动消失 —— 塞不下也不该放。
工具箱的用处就是「变换完直接粘」，所以结果直接进系统剪贴板，
然后收面板、激活原目标窗口、发按键。
写之前必须在 `SelfWrite` 记一笔，否则监听线程会把这个结果当成
用户在别处复制的内容，又往历史里存一条。

**「变换 + 写回剪贴板 + 粘贴」三步是一次点击。** 起初只做到前两步 ——
理由记在 [docs/06](06-路线图与任务清单.md#点动作即粘贴这个取舍)：
自动粘贴要抢焦点、收面板，而现在**结果压根不在面板里显示**，那个
「想在结果出来后留在面板里继续操作」的场景并不存在。

模拟按键失败时降级为「已复制到剪贴板」并提示手动按 ⌘V，摘要**不**
跟着报「已粘贴」——两处都这么说就与事实矛盾了。

**3. 动作 label 改成中文，英文留给 `id`。** 设计稿里 label 是
`Format` / `Minify`。`id` 是给代码和文档看的，保持英文稳定；
label 是给人看的，界面本来就全中文。分开的另一个好处是改文案
不影响任何引用。

**4. 加了 `hint` 字段。** 一句话说明这个动作会得到什么，悬停可见。
它存在的**主要理由是 JWT**：payload 是 base64 编码的、任何人
都能解开看，签名只保证「没被改过」。这句话必须写在用户点之前
看得到的地方 —— 写在文档里没人看得到。而它只能由后端给，
因为它跟着动作的实现走。

**动作查找之外还要查「适不适用」。** `run_toolbox_action` 拿到
action id 后会再确认它对该条目的 `content_type` 适用，不适用就报
「「美化」不能用在 text 上」。UI 只会给出适用的动作，所以这条防线平时
不触发；它是给「invoke 传了别的类型的动作」兜底的 —— 否则一句普通
文本会被当 JSON 解析，报一个跟用户操作对不上的错。

判断用的是**数据库里的字符串**反查回枚举（`ContentType: FromStr`），
不是直接比枚举。这条路径有测试盯着：`as_str` / `from_str` 少写一个分支
的话，那一种类型的工具条会静默消失 —— 而它只是少几个按钮，不报错。

### SQL 那部分为什么手写切词

直接对原文做字符串替换会有两类事故：`WHERE note = 'select'` 里的
select 被当成关键字大写（改了数据），`-- 记得 select 字段` 注释里
的内容被重排（注释的位置是有语义的）。所以先切成 token，
**只对标识符 token 做关键字判断**，字面量与注释原样输出。

手写切词而不是引入 `regex`：难点全在「怎么跳过字面量」上
（`''` 是转义、`\'` 在 MySQL 也是转义、中文不能按字节切），
而 `regex` 并不在依赖表里。

**切词之后最容易错的一处是「相邻」的定义。** `group   by` 与
`group by` 一样，多词关键字之间允许夹空白。实现时按 token 下标
相邻来判，`GROUP BY` 永远合不起来 —— 中间那个 `Tok::Whitespace`
把两个词隔开了。这条错很安静：`GROUP` 单独不是关键字，
输出看着仍然像 SQL，只是没换行。同一个 bug 还让表名提取全军覆没
（`FROM` 与表名之间的空白没跳过）。

`sql.upper` / `sql.lower` 与 `sql.format` 分成三个动作，是因为
「只改大小写」不该顺带重排版 —— 用户 diff 一个查询时要的是最小改动。

### 错误处理约定

所有动作返回 `Result<String, String>`，错误要**可读且能指导下一步**：

- ✗ `不是合法的 JSON，无法处理（expected value at line 1 column 2）`
  —— 而不是 `parse error at line 1 column 5`
- ✗ `header 段不是合法 JSON（...），可能不是 JWT` —— 而不是 `InvalidPadding`
- ✗ `base64 长度不是 4 的倍数（去掉空白后 6）` —— 给出具体数值
- ✗ `解出来不是合法 UTF-8 —— 它编码的多半是二进制，不是文本`
  —— 用户下一步多半是想存图片而不是文本

这些文案是**测试逼出来的**，不是设计出来的：`format_never_touches_literals`、
`format_never_touches_comments`、`verify_exp_reads_seconds_not_milliseconds`
各自对应一类真实踩过的坑，见 DEVLOG。
